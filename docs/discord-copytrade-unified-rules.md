# 跟单统一修复与交易员独立消息规则

本次变更仅在仓库实施，部署、编译、重启以及交易员配置由操作者手动执行。历史信号不会自动补单；CMM 历史 QNT 不补执行。模型服务余额不足按已充值处理，不是本次修复目标。

## 根因与实现边界

| 根因 | 实现 | 复用决策 |
| --- | --- | --- |
| 文字画像无法约束确定性分支，同一种双价格文案解释不一致 | 每交易员增加双价格语义和默认减仓比例；提示词、解析后规则、信号重试共用版本化规则快照 | 扩展现有画像、来源分段与解释流程，不增加规则引擎 |
| 多个 `entry_orders` 只取第一项 | 校验完整组合，支持市价＋限价，其他组合明确拒绝；两笔共享风险预算，第一笔保护确认后才提交第二笔 | 复用分批订单账本、稳定客户端 ID 和恢复机制 |
| Binance 内部原始止损与实际 tick 价格不同，OKX 查询返回张数 | 止损统一归一化；OKX 查询统一返回基础币数量；查询/解码失败不返回部分成功结果 | 提取共同止损核对逻辑，可选接口扩展 Binance/OKX |
| 止损取消后提交超时可能重复提交 | 持久化旧订单、目标、客户端 ID 和阶段；不确定结果先按身份核对；明确拒单尝试恢复旧保护 | 新增最小保护意图，复用上下文乐观锁 |
| 同义动作因为省略字段/空数组而获得不同 ID | 规范化价格、列表和条件语义，并比较历史动作 payload；保留旧动作识别能力 | 扩展动作账本，不重写旧 ID |
| 作者仓位/杠杆被当成跟单条件；复合指令条件丢失 | 仅排除明确的作者参数说明；保留加仓成交、重仓、TP 成交等条件，约束对应子动作 | 扩展来源策略和已有成交证据检查 |
| TP 更新跳过已成交档位后丢失待分配数量 | 已成交档位保持不变；部分成交先扣除，未完成权重重新归一；明确 runner 比例保留；撤单后重新读持仓 | 提取剩余分配函数，复用 TP 账本和稳定代次 |
| 独占只覆盖部分开仓路径，账户恢复依赖当前绑定 | 所有跟单 OPEN/ADD 准入检查持仓与同方向挂单；事务归属记录、冻结账户、账户事务锁；禁止活跃绑定/凭证替换及删除承载活跃交易的交易员 | 扩展已有账户检查，独立新增最小归属和事务锁表 |
| 提交前拒绝与提交结果不明混为一类 | 分为 `preflight_rejected`、`rejected`、`uncertain`、`done`；明确拒单允许新修订重新校验，结果不明不重发市价单 | 扩展动作阶段与恢复扫描 |
| 失败 AI run 未关联信号，回放文案夸大检查范围 | 模型/解析失败也关联 run；空响应有限重试，余额/认证错误不重试；回放显示“识别校验通过”及未检查门槛 | 复用已有 AI 记录、重试次数和 TTL |

首次保护、显式移止损、自动保本和周期恢复使用共同止损路径。查询失败不会被当作缺少保护，也不会仅因此触发紧急平仓。已有更严格、归属明确且数量足够的止损保留。

## 配置与业务行为

新增配置均为可选字段：

```json
{
  "market_dual_price_mode": "legacy",
  "default_reduce_ratio": 50
}
```

- `market_dual_price_mode`：`legacy` 沿用原解释、`range` 进场区间、`market_then_limit` 市价＋限价、`reject` 歧义跳过。原文明确说明区间或两笔时，以原文为准。
- `default_reduce_ratio`：明确要求减仓但没有比例时，减掉**剩余仓位**的该百分比，范围 `(0,100]`。旧配置缺省为 50；原文明确比例优先。
- 市价＋限价目前要求 Binance、`by_loss`。没有明确分配的标准双价格卡按两笔各 50% 风险预算计算，并按总名义金额、保证金、交易所精度及最小下单额共同约束。
- “市价 A—B”的 A 是市价偏离参考，B 保留为第二笔限价。第一笔不符合市价准入时整条拒绝。限价必须在当时市价和止损之间；不擅自把已经越过的补仓价变成追价单。
- 第一笔实际成交、止损建立后再提交第二笔；按实际成交风险、最新可用余额缩减第二笔，不能放大第二笔原计划数量。
- 普通单笔、原有参考价分批和区间进场仍走原策略；历史上下文不因新规则变成新的开仓。
- 止盈仍最多三档。超出目标保留在解释/事件记录中，界面提示档数上限。
- TTL 和挂单期限拒绝负数、非整数和溢出值，`0` 保持关闭对应超时的含义。新挂单截止时间冻结，旧有已存截止时间继续有效；没有截止快照的旧版订单保持旧版超时兼容路径。
- `source_channel_ids`、`reasoning_effort` 仍可读取旧值，但未实现；新保存会明确拒绝，界面可清除预留值。未顺带启用其他功能或删除无关代码。

建议手动设置：

| 交易员 | 结构化规则 | 画像补充 |
| --- | --- | --- |
| CMM | 双价格选“市价＋限价”，默认减仓 50%，保留本地风险金额和杠杆 | 信号卡是开仓来源；操作通知是管理来源；收益播报、引用旧卡不重新开仓 |
| TYLER | 保持原风格及进场策略；默认减仓 50% | 作者仓位/杠杆说明不改变本地执行参数；报喜不是主动减仓；重仓、补仓、TP 成交条件必须保留 |
| jonzi | 保持原进场行为；默认减仓 50% | 识别编辑卡片、双语重复、移动止损及结束状态；相同语义不重复执行 |

两个 Binance 账户按各自的 `exchange_id` 独立管理。本期沿用一账户一配置约定，不推测不同 API 密钥是否属于同一物理账户。

## 存储迁移与恢复

通过现有 GORM 增量迁移新增字段和表，不删除历史数据：

- 上下文：冻结 `exchange_id`、入口信号 ID、规则快照、请求止损价、实际止损价、止损订单身份/持久化意图、TP 更新意图及最近完成的 TP 更新信号 ID。
- 信号与 AI run：`rules_snapshot_json`，包含规则版本、风格、画像和两个结构化选项。
- 动作：消息修订和执行阶段；原 ID、payload 和订单累计成交继续保留。
- `copy_trade_ownerships`：账户＋币种＋方向的唯一归属。
- `copy_trade_account_fences`：串行化同账户准入与绑定/凭证变更的事务锁记录。

旧交易先检查冻结绑定；旧版没有冻结字段的上下文，在当前唯一配置下补入绑定后继续原执行版本恢复。历史账户曾经被换绑且无法还原时，应先人工核对，不能靠当前配置推断历史物理账户。

恢复处理包括 CANCEL、UPDATE_TP、没有交易上下文的动作和终态交易遗留订单。只有唯一账本关系才能补齐上下文关联。终态订单依据交易所实际状态完成取消/成交核对，避免旧的 `NEW` 账本永久阻塞后续信号。

无法确认归属的旧保护保留，并记录人工核对提示。提交结果不明且通过当前订单查询仍无法证明结果的动作保持冻结，不自动重发。平仓后仍无法确认的止损提交需核对交易所历史；不能仅因当前无仓位就假定该请求从未被接收。

其他交易所继续使用原交易接口；本次没有宣称为所有适配器补齐稳定客户端 ID 恢复能力。缺少该能力的旧路径遇到不确定提交，继续保守阻止重复操作。

## 验证

测试使用脱敏文案、临时 SQLite 和模拟交易所，不通过真实下单验证。

- 新业务回归：CMM QNT/NEAR/AXTI 双价格、DASH 作者参数和复合条件、历史 nil/空数组动作身份、stop tick 幂等、查询失败、止损丢失应答及拒单恢复、部分成交和 TP 取消竞态、数据库写入失败、账户独占与独立账户、规则快照、已结束交易释放归属。
- 存储回归：两个独立数据库连接并发取得归属时只能成功一个；活跃账户不能更换凭证。
- 适配回归：OKX 正常挂单/保护挂单张数转换，查询/解析失败，整仓止损标记；Binance `TRADIFI_PERPETUAL` 能力和实际 tick 提交。
- 前端回归：新选项保存、旧风险参数保留、减仓比例边界；原有日志、生命周期和配置测试。
- 全量 `go test ./...`、`go build ./...`，相关八包 `-race`，前端 `npm test -- --maxWorkers=2`（15 个文件、190 项测试）及 `npm run build` 均通过。前端限制测试并发，避免本机 worker 启动超时。

## 手动部署与检查

1. 先按现有运维流程备份 SQLite，确保包含 WAL 中的已提交数据；记录当前运行版本和三个交易员配置。
2. 拉取本次提交，按现有流程编译前后端、重启。首次启动执行增量迁移；若迁移报错，先处理迁移，不能以旧表结构启动新执行器。
3. 核对三个交易员绑定账户，尤其确认 CMM 与 TYLER 各自的 Binance 配置。不要在持仓、挂单或结果不明时换绑/换凭证。
4. 在 CMM 配置中手动选择“市价＋限价”。TYLER、jonzi 保持原进场设置，并按上表完善画像。保存后检查配置回显。
5. 查看新消息的规则快照、解释、动作、订单腿和实际成交。确认有效止损不再周期性撤建，TP 剩余覆盖正确，独立账户互不阻塞。
6. 回放用于检查识别，使用当前规则、上下文和价格；它没有重现历史余额、账户归属、合约权限和成交条件，不是实盘下单成功率或历史收益回测。
7. 不重跑旧 QNT 信号，不手工把 `uncertain` 改为可执行。回滚前先核对新版本未完成的止损/TP 意图；旧版本无法理解新增恢复字段，不应直接降级接管这些中间状态。
