# Discord 市价参考价与执行状态

## 本次修复的根因与边界

`進場：市價-11.073` 表示市价进场意图，`11.073` 是博主参考价。LINK 历史样本已经被正确识别为 MARKET；该交易员实际保存的山寨币偏移阈值为 0%，因此不利价差会转为参考价限价单。创建页面的默认 1% 不等于已有交易员的保存值。历史记录没有当时市价，无法推算精确价差，也不能保证将阈值设为 1% 后该历史订单就一定成交。

同时修复同类中文表达解释不稳定、MARKET 参考价遗漏合理性检查、正阈值等号浮点误差，以及信号处理状态容易被误解为成交的问题。

## 保留的价格规则

- 做多时市价低于或等于参考价、做空时市价高于或等于参考价，直接按市价进场。
- MARKET 携带参考价时，不利价差在阈值内可按市价进场；超出则挂参考价限价单。0% 不容许任何不利价差。
- 纯市价、无参考价的行为不变。负参考价拒绝；正参考价复用原有 60% 价格合理性检查，拦截 `42.573` 对应实时 `2.573` 等位数错误。
- 固定限价单仍受“阈值内限价改市价”开关控制；博主明确要求市价的单子不受这个转换开关控制。
- 区间单保持原规则：区间内或优价按市价，不利侧按区间中点挂限价；点价偏移阈值不用于区间单。
- 仅正阈值增加 `1e-9` 个百分点的数值容差，使数学上恰好 1% 的价差不会因浮点误差被排除。

## 记录与界面

提示词版本升级至 `copytrade-v4`。每次进场决策通过 `copytrade.entry.decision` 的 `context_json` 保存同一次决策所用的博主意图、价格表达、参考价、市价、不利价差、阈值、转换开关、计划类型/价格及原因。

信号原始状态 `executed` 与去重语义保持不变，界面显示“已处理”。查询接口附加可选 `trade_state`，只对唯一关联交易展示待成交、已开仓、超时撤单等当前状态；多指令或无法确认关联的记录不推断整条信号已成交。详情合并信号事件和 `reconcile-<交易上下文 ID>` 对账事件，进场方案与后续提交、成交记录分别显示。旧数据缺少快照时明确提示无法还原价差。无需数据库结构迁移。

## 验证

固定样本位于 `testdata/copytrading/market_reference_regressions.json`。其中 `response` 用于离线回归，`historical_response` 保留脱敏后的历史误判，行情字段为测试输入，不是对历史实时行情的还原。

2026-09-19 使用当时配置的模型做了隔离识别验证，只发送脱敏样本和新提示词，不调用交易执行、不写入生产跟单记录。四个结果符合预期：LINK、修正后的 ICP 为 MARKET 并保留参考价；错误 ICP 为 AMBIGUOUS；引用旧开仓信息的 LINK 获利播报为 IGNORE。这是本次样本验证，不代表模型以后所有输出都必然正确；确定性校验继续保留。

回归命令（前端命令在 `web` 目录执行）：

```sh
go test -race ./copytrader ./discord ./store ./api
npm test
npm run build
```

覆盖做多/做空、0%/1%、等号边界、限价转换开关、区间、参考价错误、缺少止损、无行情、穿越止损、重复/编辑消息、回放无副作用、日志快照、唯一交易关联、限价成交与超时撤单、查询隔离及前端错误重试。

## 部署与配置

由维护者拉取代码、编译并重启。更新不会覆盖已有配置，也不会补执行历史 LINK/ICP 信号或更改旧订单。

若决定采用山寨币 1% 的设置，应在目标交易员的**编辑入口**核对并保存；BTC/ETH 可保留已保存的 0.2%。这是独立的实盘配置决定，本次代码更新未执行该调整。保存会重载运行配置，请在部署时自行安排。部署后可在新信号的“查看 AI 与执行详情”中核对实际使用的阈值。
