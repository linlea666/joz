# 单参考价「优先参与」入场策略

## 背景与适用范围

此前 BTC「市价-85100」、STX「市价-0.4147」因为不利偏移超过配置阈值，正常进入了参考价限价分支。此次新增可选策略，允许用户选择先承担一部分计划风险参与，再等待参考价补入；不是修复旧策略，也不保证收益改善或成交。

仅支持 Binance、以损定量，以及新开仓流程中只有一笔 MARKET、且带一个正数参考价的情形。不改变双价格语义、区间、纯市价、普通限价或管理指令的解释与路由。已有的 ADD 无关联持仓转新开仓逻辑保持不变，进入新开仓流程后同样使用所选策略。作者明确两笔时仍保留原首笔偏移准入，不叠加本策略。

## 启用

用户更新服务器：

```bash
cd /opt/nofx && ./start.sh update
```

编辑对应跟单交易员，在 **单参考价市价信号的执行方式（市价 A）** 选择：

> 优先参与：不利价各半风险，首笔不受偏移限制

保存后确认配置重载与运行状态。上面的“双价格文案含义（市价 A—B）”继续按原需要设置，不是本次新增选项。

配置值为 `entry_policy=market_reference_participate`。安装与更新不自动选择它；旧配置不改写，无数据库迁移。不修改风险金额、杠杆、偏移阈值、运行模式、挂单有效期、止盈档数或现有订单，不补执行历史消息。

## 决策规则

| 价格关系 | 新策略 |
|---|---|
| 有利或相等：多单市价不高于参考价，空单市价不低于参考价 | 单笔全额市价，仍受风险与交易所限制 |
| 不利：多单市价高于参考价，空单市价低于参考价 | 首笔 50% 计划风险市价；第二笔 50% 计划风险参考价限价 |

不利分支不使用 BTC/ETH、山寨币偏移阈值拦截首笔，阈值为 0 也如此。系统继续记录偏移和阈值，明确标注“不用于拦截”。阈值仍对其他原有入场分支有效。

“50%”是风险预算，不是数量或保证金各半。两笔分别按各自入场价与止损的距离计算数量，再受保证金、名义价值、精度和最小订单额限制。无法满足最小订单额时拒绝组合，不擅自改成全额市价。首笔滑点增加已用风险时，第二笔按实际剩余预算缩量；费用、跳空和止损滑点可能使实际亏损超过计划值。

首笔成交且保护得到确认后，复用现有执行器提交第二笔；部分成交先保护，不立即提交第二笔。提交结果不明按原客户端身份查单，不重发市价。减仓、止盈成交、保本、订单到期等继续沿用原有后续入场限制。

来源、唯一关联、重复开仓、消息时效、账户归属、合约状态、价格合理性、止损／止盈方向、资金和保护检查保持有效。没有增加最低盈亏比门槛，也不会为获得成交而移动原止损、止盈。

## 可追踪性与兼容

- 入场配置保存在消息规则快照中。已接收消息按既有快照及配置变更执行边界处理，已建立订单按持久化计划恢复，不随新选项重新拆单。
- 执行事件保存 `entry_policy`、`origin`、报价、参考价、偏移、阈值、`threshold_applied=false`、预算和实际计划腿。
- 跟单详情区分已选策略、实际采用规则及订单结果；旧记录缺少字段时不从当前配置推断。
- 识别回放新增入场形态预览，使用回放时的规则与行情。它不检查资金、账户下单权限及全部执行条件，不计算可成交数量，不下单，也不是历史成交证明。旧回放不自动重算。
- 持久执行上下文仍使用既有分批执行标记来运行保护与风险核算；实际选择的策略以规则快照和决策事件为准，避免重写既有恢复协议。

## 回归与上线核验

新增回归覆盖：多空、有利／相等／不利、零阈值、阈值边界、BTC/STX 历史价格、共享预算、滑点后缩量、最低订单额、首笔保护失败、部分成交、确认丢失、重启查单恢复、配置冻结、执行边界，以及回放只读。

继续运行原双价格／区间／单参考价组合测试和 TYLER、CMM、jonzi、来源与去重、账户归属、订单保护恢复测试。

更新后先核对选项及保存状态；通过识别回放确认形态与预期一致。真实新消息的最终结果仍应以订单账本、成交与保护状态核实，不以“识别通过”代表成交。本次开发不操作生产订单或发送邮件。
