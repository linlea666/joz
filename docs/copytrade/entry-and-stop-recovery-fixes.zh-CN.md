# 入场规则展示、止损恢复与管理话术修复

## 修复范围

本次基于 2026-10-13 的 STX、RAY、W、HYPE 和 BTC 样本。继续使用既有解析协议、风险计算、订单账本及恢复循环，不改变 BTC/ETH 0.2%、山寨币 0.5% 的现有配置，不改变风险金额、杠杆、三档止盈上限、挂单有效期或运行模式。不补执行历史信号，不主动撤销现有挂单。

### 入场含义

“按偏移分配：阈值内各半风险，超阈值参考价限价”应用于一个数字参考价的市价信号。`市價-0.4147` 是一个参考价，不是两笔价格。

- 有利或同价：全额市价。
- 不利偏移在配置阈值内（包含边界）：两笔各占 50% 风险预算，数量不必各半。
- 超阈值：全额参考价限价；阈值为 0 时所有不利价格转参考价限价。
- 两个数字价格、纯市价、普通限价继续按各自既有规则，不重复拆分。

历史回归输入 STX 0.4147/0.423（0.5% 阈值）、CHZ 0.01496/0.01589（0.5%）、BTC 空单 85100/83829.2（0.2%）均产生一笔参考价限价。这是当时决策依据，不是当前行情建议。

配置区直接显示表单中的两类阈值；日志详情仍读取当时已保存的决策与规则快照。信号原始 `status` 不变，展示另据订单账本区分等待成交、部分成交、已成交、未成交终止和提交待核对。

### 止损恢复

根因是明确的 `-4509` 拒绝被记为 UNKNOWN，同时恢复仅查询未完成条件单；订单结束后无法核对，反复记录相同告警。

- Binance 明确拒绝保留原错误类型，新增 `-4509` 分类。止损意图 JSON 增加 `error_code`、`error_stage`、`error_at`，仍沿用原客户端身份和状态字段。
- 明确拒绝后重新读取仓位；空仓不盲目恢复旧止损，有仓位才继续保护。`-4509` 后重新确认仓位出现时，下一次保护扫描使用新身份，绝不重发未知结果请求。
- 新增可选 `StopOrderReader`；Binance 用既有 SDK 按 algo ID 或 client algo ID 精确查询，检查身份、币种与方向。引擎同时检查交易员和交易所账户绑定。
- 有实际子订单的条件单还要核验子订单终态；父单触发不等于子单已经结束。取消、过期、拒绝或已结束且子单终态的可靠证据才允许解除未确认意图。
- 清理前后均读取新鲜仓位。查询失败、身份冲突、缺少历史、活跃子单、仓位重新出现时不提前释放保护记录。
- 同一交易/阶段的相同恢复错误首次记录、约每 60 秒汇总重复次数；状态改变和恢复另记。扫描频率不受日志汇总影响。
- `recovery_error` 是信号和动作查询的附加只读字段。空仓但未解决的收尾显示“空仓已观察到，恢复事项待核对”，原交易状态不伪造为 CLOSED。

### 旧 UNKNOWN 的处理边界

旧 W 意图没有保存提交错误码。即使附近文本日志出现 `-4509`，本次更新也不会用宽松时间匹配将旧意图改写成“明确拒绝”。

更新后系统会按原身份尝试核对；只有可靠证据才能自动收尾。查不到不等于从未提交：Binance 明确规定条件单历史有保留期限。[查询条件单文档](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade#query-algo-order-user_data)

若仍待核对：保留上下文和日志，核对同一账户、币种、方向、原条件单身份、对应成交及当前仓位/挂单。不要直接删 UNKNOWN、删交易上下文、修改终态或重放旧信号来解锁。证据不足继续保留限制；人工修复需单独审阅明确证据与处理范围。本次不提供绕过保护的一键清除。

### 管理话术和合约限制

- “止盈全部仓位／倉位”共用全平意图判断，确定性与 AI 校验一致；否定、条件、比例、引用和目标关联限制保留。
- 同时要求全部退出和保留仓位属于冲突，不产生全平指令。
- 收益描述带尚未完整理解的管理建议交给 AI，随后仍受共同校验。没有目标交易仍跳过，不回补旧 HYPE/BTC 动作。
- RAY `SETTLING` 等明确限制用 `CONTRACT_NOT_TRADING` / `CONTRACT_UNAVAILABLE` 展示；查询失败用 `CONTRACT_CHECK_FAILED`，不冒充“不支持合约”。不切换币种或交易所。
- 回放同时保留行情与合约检查；两者都失败时摘要优先已确认的合约限制。旧回放标注“历史版本结果”，不自动补算。
