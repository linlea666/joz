# 消息识别审计修复与回放检查

## 修复依据与范围

2026-10-10 的线上记录表明，采集已恢复，新的 ETH、LUMIA 消息可以进入解释链路；当前观察模式不会创建交易订单。此次处理后续审计发现的四类问题，不调整仓位计算、订单提交、止盈止损、账户归属或恢复算法。

1. TYLER 的确定性解析只提取命中的动作，可能将“减仓上套保”当作完整减仓指令，或将带可选管理操作的收益播报当作纯报喜。现在“上套／套保”等尚未定义的保护含义，以及减仓与保本／继续持有之间的替代选择，标记为歧义。共同后置校验也执行此边界，AI 不能绕过。明确的“减仓25%，上成本”和已有“止盈或者减仓”同义口令保持原行为；引用旧卡不会覆盖当前指令。
2. 旧回放把当前行情参与校验产生的错误统一归为解释错误。现在每条子指令分别保存来源证据、原文参数、当前行情、当前合约的检查结果。参数检查复用现有校验函数，以作者写出的参考价检查；缺少原始市价参考时明确标注无法验证历史价格关系，不猜测当时行情。当前报价错误、合约非交易状态、查询失败分别呈现；管理指令无需当前报价的检查不强行依赖报价。
3. 原频道状态只在连接状态回报时刷新进度，且旧回报可能擦除新进度。现在与接收事务共同记录消息进度和接收时间，重传、晚到消息、旧状态帧不使进度后退。此字段仍不能替代 Gateway 心跳、频道权限、缺口核验。不会根据某一条消息就把频道标成正常。
4. 超过开仓和管理两类有效期的新任务，现在在准备媒体、上下文及 AI 调用前跳过，保留原消息供关联。任一有效期设为 0 时不使用此优化；新编辑使用编辑时间；已有解释、执行与恢复任务继续按原流程处理。

## 日志和统计

- 确定性解释新增 `copytrade.rule.matched`，不再产生虚假的 `copytrade.ai.request` / `copytrade.ai.parsed`。
- 分类事件附带 `processing_path` 与 `model`；恢复复用已保存解释时标记 `stored_interpretation`。
- 跟单状态展示实际客户端模型、AI 调用和规则处理数量。统计范围是当前保留的在线解释记录，包含失败调用，不含识别回放，不是终身累计，也不是 SDK 内部 HTTP 重试次数。AI 原文清理后数量可能减少。统计查询失败显示不可用，不假装为零。
- 回放继续使用“识别校验通过”；它不核验历史持仓、资金、订单精度、执行边界等完整执行条件，不能据此补执行历史信号。多指令逐项显示检查结果。

## 更新与数据兼容

```bash
cd /opt/nofx && ./start.sh update
```

保留现有配置、运行模式、凭证、数据库和采集缓冲。数据库只增量增加回放检查 JSON、处理路径和模型字段；旧回放显示未保存分层证据，不用当前行情改写历史报告。历史信号和已完成动作不重算、不补单。

更新后检查：

1. 保持当前“仅采集验证”，检查服务健康、Gateway 心跳、配置应用版本及频道核验状态。
2. 等待一条真实新消息，验证频道最后消息进度、投递、解释和结果；没有新消息时仍为等待验收。
3. 回放历史 RAY／OGN 等样本，核对原文参数与当前行情／合约结果分开显示。“上套保”样本应显示歧义，明确管理口令保持正常。
4. 检查模型名称、规则处理事件及保留期内的统计数量。日志变更仅影响新产生的记录，旧文本不会改写。
5. 若需启用正常执行，由用户在确认后操作。此次修复不自动改变执行模式，不通过真实下单验收。
