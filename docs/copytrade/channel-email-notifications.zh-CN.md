# 独立频道邮件通知

## 更新与启用

```bash
cd /opt/nofx && ./start.sh update
```

本次按增量方式增加通知投递表、来源快照字段和独立配置。保留现有 Discord/SMTP 凭证、异常告警收件邮箱、交易员、订单、采集缓冲和运行模式。无需增加容器、修改环境变量或重新初始化数据库。更新后功能默认关闭。

打开「设置 → Discord → 频道消息邮件通知」：

1. 在上方邮件服务区域保存有效 SMTP 配置。新通知复用发件服务，不复用异常告警的收件邮箱和开关。
2. 填写一个独立的频道通知收件邮箱。
3. 输入频道 ID，逗号或换行分隔，点击「添加到列表」。最多 20 个频道，重复 ID 自动去重；可填写备注、逐项停用或删除。
4. 勾选「启用频道消息通知」，点击该区域的「保存频道通知」。添加、删除和编辑在保存后生效；关闭弹窗不会保存未提交的修改。
5. 点击「刷新通知状态」，确认配置应用及频道权限就绪，再用启用后的真实新消息验收。
6. 「测试通知邮箱（不保存）」只使用当前收件邮箱和**已保存 SMTP**，不会保存表单，也不会修改 Discord 或触发跟单。测试由用户主动点击。

无需创建交易员。「仅采集验证」与「正常执行」都可以发送频道通知；全局「消息采集开关」必须开启。新功能不改变原来的「采集异常邮件告警」。SMTP 接受邮件只代表邮件服务受理，不保证到达收件箱。

## 行为边界

- 每条符合条件的实时新消息一封，包含普通正文和回复，也包括机器人/APP 消息。没有交易关键词过滤，不调用 AI、不生成信号、动作或订单。
- 只监控配置的频道 ID，不自动监听子线程。编辑、删除、表情反应和频道系统事件不发邮件。
- 首次启用、断线补读、Resume 重放、程序重启和旧缓冲均不补发。旧版采集协议没有实时资格字段时，不发送通知。
- 邮件保留首次接收内容：频道备注/ID、作者、北京时间 UTC+8、正文、附带/引用卡片文字、最多 10 个附件链接和原消息链接。正文最多 16 KiB，截断会提示且保留原消息链接。不下载图片、不 OCR、不额外请求引用消息。
- 修改邮箱、停用或删除监控会取消尚未发送的旧任务；已经开始发送的邮件不能撤回。重新启用或删除后重加不会重发旧消息。
- 仅对明确临时失败重试：第一次失败后等 15 秒，第二次失败后等 45 秒，总共最多 3 次，且从首次接收起最多 2 分钟。认证、证书及永久拒收不重试；DATA 提交结果不明不重发。
- 发送采用独立串行任务，最多 1,000 个未完成任务；过期/满额明确记录。更新或重启会取消旧待发送任务，原发送中任务转为结果不明。
- SMTP 成功后若数据库结果提交失败，任务不会再次进入 SMTP；记录存储故障，数据库恢复后将超过 30 秒的未完成发送标记结果不明。日志写入失败不改变交易结果。

## 隔离与复用

采集器仍是原来的唯一账号连接。实际订阅是「运行中的跟单来源＋启用的通知频道」的去重并集，共享频道仅采集一次。

```text
Gateway → 原持久缓冲 → Go 原入库确认
                         ├─ 原交易员投递 → 解释/风控/执行
                         └─ 独立通知扫描事务 → 邮件任务表 → SMTP
```

新增通知频道只核验新增/受影响频道；通知专用频道仅校验访问和订阅，不读取历史。增删通知不重启交易员、不重连健康 Gateway、不改变交易执行边界。通知的应用版本与交易路由版本分别核对，通知频道权限失败不拒绝健康跟单路由。真实连接、凭证和跟单来源故障仍遵循原保护。

通知任务使用「监控 ID＋启用代次＋频道 ID＋消息 ID」去重，同文案不同消息不合并。首次接收快照与实时资格冻结保存；后端和采集器分别保护重启边界。通知入队与扫描进度在独立事务提交，SMTP 等待和邮件记录失败不参与跟单消息确认。

仍共享 CPU、数据库和采集缓冲，高流量下不能承诺资源完全无影响。长期高流量导致过期或满额时，应减少监控频道或重新评估通知频率，不把失败邮件伪装为发送成功。

## 状态与排障

各频道显示应用状态、权限状态、最近消息及邮件结果。「查看通知日志」打开日志中心，预填 `channel_notify` 模块及频道筛选，可使用原有 CSV/JSONL 导出。

| 状态 | 含义与处理 |
|---|---|
| 等待配置 Token / 全局采集关闭 | 配置凭证或开启消息采集；不会自动改运行模式 |
| 等待应用 | 检查后端与采集器均更新；旧采集器不会发送通知 |
| 核验中 / 无访问权限 | 核对频道 ID 与当前账号权限；不影响其他已就绪跟单来源 |
| 待发送 / 等待重试 | 独立发送队列；最多存活 2 分钟 |
| SMTP 已接受 | 检查收件箱、垃圾邮件及服务商投递限制 |
| 发送失败 | 查看安全错误类别，核对 SMTP/授权码/收件地址 |
| 结果不明（不重发） | 可能已经提交；人工核对邮箱，不自动重发 |
| 已取消 / 已过期 / 队列已满 | 无补发；查看配置变化、重启、发送延迟或流量 |
| 通知记录不完整 | 通知存储或诊断写入异常；修复存储，原跟单账本不因邮件错误改变 |
| 配置版本冲突 | 关闭并重新打开设置取得最新配置，再编辑保存，避免覆盖其他编辑者 |

通知终态投递记录保留 30 天，由现有日常清理任务处理。日志中心继续沿用其实际系统日志保留配置。清理通知不删除交易、订单、去重或恢复证据。

新增接口均沿用全局 Discord 设置的登录权限：

- `GET /api/discord/channel-notifications`
- `PUT /api/discord/channel-notifications`（配置版本校验）
- `POST /api/discord/channel-notifications/test-email`

接口、邮件任务和诊断日志不包含 SMTP 授权码；查询/日志不暴露完整邮件正文和收件邮箱（配置查询仅向有权限的登录用户显示其配置邮箱）。
